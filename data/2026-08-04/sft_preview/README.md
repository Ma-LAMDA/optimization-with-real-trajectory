# q0001 第一条 accepted 轨迹的推理切片预览

本目录只用于审阅新的 SFT 转换思路，尚未替换 `sft/` 下的正式训练与验证数据。

`q0001_success_01_reasoning_steps.jsonl` 把一条 accepted 轨迹按 5 个有价值的 Agent
推理节点拆成 5 条 SFT：初始计划、候选假设、证据更新、候选排除和最终决策。原轨迹中
不影响最终归因的绕路已剔除；原始消息和完整事件仍保留在 `raw/` 中供追溯。

## 原生多轮消息

预览使用 ms-swift 4.4.2 的原生 Agent 消息格式：

- `system`：排障和时间边界规则；
- `user`：原题与答案格式，只出现一次；
- `assistant`：当时可见证据下补写的 `<think>` 和阶段结论；
- `tool_call`：原轨迹里实际执行、且对后续归因有帮助的命令；
- `tool_response`：对应命令的真实结果摘录、退出码和状态。

第 N 条样本保留第 1 至 N 步的原生消息前缀，并在第 N 步 assistant 与实际工具调用后
结束，因此不会看到这些调用的未来结果。第 N 步调用结果只会从第 N+1 条样本开始作为
`tool_response` 出现。最终节点只输出推理和 `<result>`。

为控制多轮上下文长度，上一节点刚返回的结果保留真实原文摘录；更早的历史结果改为
已确认的关键事实和关键值，历史命令仍保留原文。一次性目录发现结果在完成对应阶段后
不再重复展开。完整结果可通过 metadata 中的来源事件和哈希回溯。

命令结果只删除重复、无关和未被推理使用的部分；保留片段不改写原文。同一推断需要
多个方向相互印证时，相关命令合并为一个逻辑证据组。第 4 步从 10 条独立证据压缩为
5 个逻辑证据组、8 个命令，删除了重复的接口利用率和 VRRP Backup 回显。

第 4 步原消息只沿 OSPF 方向继续排查，属于非最优绕路，已替换为“先核验 STP；若
STP 正常再核对 OSPF 度量”的证据约束目标。第 5 步继承优化后的路径，不再携带该绕路。

## Loss 规则

当前训练脚本使用 `--loss_scale default`。如果不写逐消息标记，ms-swift 会让历史
assistant 响应也参与 loss；同一早期步骤会在多个前缀样本里被重复监督。

本预览显式使用逐消息 `loss_scale` 字段，并把 `<think>` 与阶段结论拆为两个连续的
assistant 片段：

- 当前节点的 reconstructed `<think>` 权重为 `0.4`，降低对单一措辞的逐 token 过拟合；
- 当前阶段结论或最终 `<result>` 权重为 `1.0`；
- 当前节点随后发出的 `tool_call` 权重为 `1.0`，用于精确学习下一步取证动作；
- 历史 `assistant` 和历史 `tool_call` 权重全部为 `0.0`；
- `system`、`user`、`tool_response` 与 padding 只提供上下文，不计入 loss。

因为包含 0.4 非二元权重，0804 训练必须设置 `--is_binary_loss_scale false`。这些权重
由生成脚本逐条校验。正式批量生成和训练前，还需要用目标模型 tokenizer
检查每条原生多轮样本的 token 数；0804 训练 profile 使用 `max_length=16384` 和
`truncation_strategy=delete`，超长样本会被整条删除，不能仅凭字符数判断是否可训练。
模型的 262,144 token 原生上下文是能力上限，不作为单卡 BF16 LoRA 的默认训练长度。

语义相似度不直接替代 SFT 交叉熵。后续 0804 对齐阶段再把根因正确、证据一致、较早进入
正确归因路径和少绕路组合成 DPO/GRPO 的序列级奖励；工具参数和最终结果继续严格校验。

## 审计信息

每条样本的 `metadata` 保存来源事件行、item ID、命令/完整输出/摘录哈希、累计关键证据
账本、证据选择原因和 loss 策略。metadata 只用于审计，不会被模型作为消息内容训练。
所有样本仍标记为 `draft_preview`，确认后再批量转换。

重新生成：

```powershell
python -B scripts/generate_q0001_reasoning_step_preview.py
```
