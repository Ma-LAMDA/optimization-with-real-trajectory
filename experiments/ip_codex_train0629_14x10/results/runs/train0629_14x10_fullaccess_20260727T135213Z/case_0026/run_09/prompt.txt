## 离线组网配置查询 Skills

你可以通过文件系统只读查询本题对应的组网配置和设备命令回显。所有数据均为预先采集的固定快照，不是实时设备，也不支持执行新的 CLI 命令或调用远程接口。

### 数据根目录

从当前工作区定位仓库根目录，并使用仓库根目录下的相对路径：`saved_configs`。

只允许在已定位的 `saved_configs` 根目录内列目录、搜索和读取 `.txt` 文件；不得修改、创建或删除任何配置文件。

### 数据模型

目录结构固定为：

`saved_configs/<project>/<node>/<command_key>.txt`

- `<project>`：网络项目名，等价于原查询方式中的 `project_id`。
- `<node>`：设备节点名，等价于 `node_id`。
- `<command_key>.txt`：该节点上一条已采集命令对应的文件名。
- 文件内容：该命令的固定回显，等价于查询结果中的 `output`。

注意：`command_key` 是适合文件系统保存的命令标识。CLI 命令中的空格、斜杠、管道符或过滤条件等可能已被转换为下划线；不要假设存在通用且完全可逆的转换规则。必须先列出节点目录中真实存在的文件名，再选择和读取文件，禁止凭空构造不存在的路径或回显。

示例：

`saved_configs/CampusNetwork_05/SW-DMZ-ACC-01/display_ip_interface_brief.txt`

表示项目 `CampusNetwork_05` 中节点 `SW-DMZ-ACC-01` 的 `display ip interface brief` 已采集回显；查询结果就是该 `.txt` 文件的完整内容。

### 必须遵循的查询流程

1. **锁定项目**
   - 先列出 `saved_configs` 下的一级目录。
   - 优先使用题目中明确给出的项目名进行精确匹配。
   - 若题目没有明确项目名，可根据题目中的节点名在各项目的二级目录中定位候选项目；只有证据唯一时才能选定。
   - 项目选定后，本题的所有证据都必须来自该项目。不得把名称相近的项目或不同项目的数据混合使用。

2. **确认节点**
   - 列出目标项目下真实存在的二级目录，以精确节点名为准。
   - 题目中的简称、角色名或大小写与目录名不完全一致时，应先通过目录名和相邻设备信息核实，不能直接猜测。
   - 涉及端到端链路、主备设备或多跳路径时，应分别查询每个相关节点。

3. **发现可用命令**
   - 先列出目标节点下的 `.txt` 文件，再按故障现象筛选文件名。
   - 可以使用文件名关键词搜索；必要时可在已锁定项目内搜索文件内容以定位 IP、接口、VLAN、VRF、邻居或路由等关键对象。
   - 只能读取已经存在的命令文件。“未找到对应文件”表示该快照没有采集此命令，不能等同于设备不存在、配置不存在或命令执行失败。

4. **按层取证**
   - 拓扑与邻接：优先查看 LLDP、接口描述、邻居类回显。
   - 物理与接口：查看接口简表、接口详情、链路状态和错误计数。
   - 二层：查看 VLAN、STP、MAC 地址表、Eth-Trunk 或链路聚合。
   - 三层：查看 IP 地址、ARP/ND、路由表、策略路由和 VPN/VRF。
   - 控制平面：按题意查看 OSPF、BGP、BFD、EVPN、MPLS、SRv6 等协议状态。
   - 安全与主机侧：按题意查看 ACL、防火墙/NAT，以及 `ip addr`、`ip route`、`ip neigh`、DNS 等主机回显。
   - 以上是选取证据的方向，不要求机械地读取全部文件。优先读取能够验证或排除当前假设的最少充分证据。

5. **交叉验证并定位故障**
   - 对关键结论至少核对配置意图与运行状态；条件允许时，再用链路另一端或上下游设备数据交叉验证。
   - 沿真实转发路径逐跳检查，明确故障发生在哪台设备、哪个接口、哪一层或哪个协议环节。
   - 区分“文件明确显示异常”“文件明确显示正常”“没有采集相关命令”三种情况。
   - 若多个文件相互矛盾，应明确指出矛盾及各自来源，不得擅自选择更符合预期的一份。

6. **形成答案**
   - 结论必须由实际读取到的文件内容支持，不得编造设备状态、配置、拓扑、命令结果或实时变化。
   - 先给出直接结论，再给出关键证据和因果链；只提出与证据一致、可操作的处置建议。
   - 如果现有快照不足以唯一判断，应说明已确认的事实、缺失的证据和仍可能的原因，不得把猜测写成确定结论。
   - 不要在最终答案中输出文件遍历过程、工具调用日志或与题目无关的大段原始回显。
